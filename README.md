# FaderFace

Play ComfyUI from an Akai APC40. Two ways in, one repo:

1. **Canvas nodes** (`APC40 Knob`, `APC40 Pad`) for workflows that run live in
   the ComfyUI browser tab with Auto Queue. Ships with an **APC40 Live Portrait**
   workflow: knobs move a face's head, eyes, brows and mouth in real time.
2. **A headless pad bridge** for image editing. Each of the 40 pads is a prompt
   preset, knobs bend the sampler, every edit can chain on the last output, and
   the pads light up while they render. Ships with a **Flux 3 Klein edit
   pedalboard** skin. No browser needed.

The two share one file, `faderface/apc40.py`, which knows what every control
on the APC40 sends (mk2 and mk1).

## Install

Clone or junction the repo into `custom_nodes` and restart ComfyUI. The canvas
nodes need two more packs, both from ComfyUI Manager or GitHub:

- `comfyui-web-viewer` (VrchStudio): its `MIDI Device Loader @ vrch.ai` reads the
  APC40 in the browser through Web MIDI.
- `ComfyUI-AdvancedLivePortrait` (PowerHouseMan): the face engine, for the
  Live Portrait workflow only. It downloads its own models on first run.

The headless bridge needs the Python deps in `pyproject.toml` (`pip install -e .`).

## The APC40 and your computer

- **Plug the APC40 in before you open the ComfyUI tab.** Web MIDI enumerates
  devices at page load. Chrome and Edge support it; the ComfyUI desktop app is
  Electron and does too.
- **Windows gives a MIDI port to one program at a time.** If your OBS plugin, a
  DAW, or the headless bridge holds the APC40, the browser sees nothing. Use
  loopMIDI to split it: point one program at the real port and have it echo to
  a loopMIDI port, and point the other program at that.
- The mk2 needs a short SysEx to let the host drive every LED. The bridge sends
  it on start. The canvas nodes never write to the controller.

## Live Portrait on the knobs

Load `workflows/liveportrait_apc40.json` (also copied into your user workflow
list as **apc40_live_portrait**), then:

1. Check the **APC40 (MIDI Device Loader)** node shows the controller's name.
2. Centre the eight device knobs so the head starts straight.
3. Leave **Auto Queue off**. FaderFace queues one run per knob move (its browser extension listens to the controller). Press Run once to load the models.
4. Click the Web Viewer node's button for a clean, full-size window.

| Control | Expression input | Range |
|---|---|---|
| device knobs 1-3 | head pitch, yaw, roll | -20 .. 20 |
| device knobs 4-5 | pupil x, y | -15 .. 15 |
| device knob 6 | eyebrow | -10 .. 15 |
| device knob 7 | blink | -20 .. 5 |
| device knob 8 | wink | 0 .. 25 |
| track knobs 1-3 | mouth aaa, eee, woo | per input |
| track knob 4 | smile | -0.3 .. 1.3 |
| master fader | crop factor | 1.5 .. 2.5 |

**Why no faders:** the MIDI loader keys CC by number only, and all eight faders
send CC 7 on different channels, so they collapse into one slot. The sixteen
knobs, master and crossfader are distinct numbers and all work. ControlFreak
(see below) does see channels if you need the faders.

The workflow is generated by `scripts/build_liveportrait_apc40.py` from one
control table; edit the table, rerun, and both the canvas file and the API file
update together. `scripts/validate_liveportrait_api.py` submits the API file to a
running server with synthetic knob values, which is how the graph was proven
without touching the controller.

## Skinning someone else's workflow

Any workflow becomes an APC40 instrument the same way:

- **In the canvas:** drop a `MIDI Device Loader @ vrch.ai`, add an `APC40 Knob`
  per parameter, pick the control by name, set the output range, wire it into
  the widget's input. `APC40 Pad` gives a boolean per pad for switches.
- **Headless:** export the workflow with *Export (API)*, write a skin JSON in
  `mappings/` that names the prompt, seed and source-image inputs as
  `node.input` (node id or title), bind knobs and pads, run the bridge.

For plain "map this knob to that widget" in the canvas with no JSON at all,
[ComfyUI_ControlFreak](https://github.com/ryanontheinside/ComfyUI_ControlFreak)
does it by right-click and is worth trying first on big graphs. This repo covers
what it does not: control by APC40 name, pad presets, output chaining, LED
feedback and running without the browser.

## The headless pedalboard

```bash
python -m faderface --list-ports
python -m faderface --skin mappings/flux3_klein_edit.json --port 8188 --source photo.png
```

- Pads: 40 edit presets (weather, medium, era, add things, grade, framing). A
  pad glows yellow while its edit renders, green when done, red on error.
- Device knobs: steps, cfg, shift, reference size, sampler, scheduler. Track
  knobs 1-2: width, height.
- Scene buttons: 1 reset to the source image, 2 toggle chaining, 3 new seed,
  4 lock seed, 5 interrupt. Play repeats the last pad.
- With no `--source`, pads run as text-to-image; the skin strips the reference
  chain automatically.
- `--dry-run COL,ROW` prints the exact prompt a pad would send, no MIDI, no server.
- Any port name works for `--midi-in`, so a loopMIDI port can stand in for the
  controller while something else owns it.

The Klein skin expects `flux3-image-klein-int8-convrot.safetensors`,
`qwen3vl_4b_int8_convrot.safetensors` and `flux2-vae.safetensors`; edit the
loader nodes in `workflows/flux3_klein_edit_api.json` for other weights.

## Status

- Live Portrait on the knobs: proven with the APC40 mkII in hand on 2026-10-27.
  Web MIDI picked the controller up, each knob move queued one run, and the

- Bridge and skins: 30 offline tests, fake MIDI ports, fake client. Not yet
  run against the controller.
